⚽ ScoutIQ — Football Data Analytics Platform
Deployed on Vercel Domain: Sports Data Analytics & Data Ingestion
# 1. Project Overview

ScoutIQ is a football data project designed to collect and organize match, team, and player information for football performance analysis. It uses Python and the Sportmonks API to retrieve football data and supports a structured workflow for processing and analyzing that information.

# 2. Problem Addressed

Accessing, structuring, and maintaining football match and player metrics across international competitions typically involves fragmented, deeply nested API structures. ScoutIQ creates an automated pipeline that ingests raw football feeds, validates response schemas, and maps them into an organized relational database for analytical query preparation.

# 3. Approach & Data Architecture
  • Data Source: Sportmonks Football API delivering detailed league, team, player, and match telemetry.
  • Data Collection Process: Modular Python REST client utilizing HTTP authentication, session handling, and rate-limiting safeguards.
  • Data Structure: Normalized relational schema in MySQL organizing fixtures, squads, players, and match statistics.
  • Data Handling: Python scripts leveraging Pandas and NumPy for raw JSON parsing, data hygiene, and tabular structuring.
# 4. Tech Stack
Programming Python
Data Analysis Pandas NumPy
Database MySQL
Data Source & APIs Sportmonks Football API REST API Requests
Deployment & VCS Git GitHub Vercel
# 5. My Specific Contributions
  • Architected and implemented a modular Python API client with authentication, headers, and rate-limiting error handling.
  • Built automated data ingestion pipelines for league, season, team, and fixture datasets.
  • Engineered relational data mapping from nested JSON responses and implemented MySQL database connection utilities.
  • Utilized Pandas and NumPy for exploratory data inspection, table restructuring, and metrics preparation.
  • Configured environment variable management to secure API credentials across environments.
# 6. Project Outcome & Value

Established a functional, automated ingestion pipeline that transforms multi-tiered football API responses into structured, queryable relational tables—eliminating manual data extraction and laying the foundation for automated performance analytics.

# 7. Planned Development Roadmap 🚀

The following analytical extensions are clearly identified as planned enhancements currently in active design:

  • SQL Analysis: Advanced queries calculating win-draw-loss trends, expected goal (xG) correlations, and home vs. away goal differentials.
  • Team & Player Comparison: Aggregated metric views for head-to-head tactical comparison across leagues.
  • Power BI Dashboards: Interactive visual reports displaying team offensive vs. defensive quadrant maps and seasonal performance summaries.

🚨 Multi-Agent Disaster Management Simulator (Disaster-OS)
Deployed on Vercel Domain: Multi-Agent Systems & Simulation Engine
# 1. Project Overview

A multi-agent disaster management simulation that explores how AI agents coordinate during disaster scenarios. My contributions included state management, event logging, and evaluation metrics used to assess agent performance.

# 2. Problem Addressed

Evaluating multi-agent coordination during crisis events requires consistent state capture, synchronized timeline logging, and quantitative metric tracking to assess whether dispatched units resolve hazards efficiently without generating false alerts.

# 3. Approach & System Architecture

Disaster-OS models simulated environmental emergencies (such as floods and wildfires) where specialized agents handle hazard detection, responder dispatch, and telemetry tracking. The system records state transitions, persists chronological event streams in SQLite, and serves simulation data through FastAPI endpoints.

# 4. Tech Stack
Backend & APIs Python FastAPI
Data Storage SQLite
Data Analysis Pandas NumPy
Machine Learning Scikit-learn
Deployment & VCS Git GitHub Vercel
# 5. My Individual Contributions

Clarification: In this collaborative simulation project, my individual focus was on state architecture, backend logging, and telemetry metrics:

  • Engineered the state management system to record agent execution status, task allocation, and state transitions.
  • Built structured event logging and incident data storage using SQLite to record simulation timelines.
  • Implemented the evaluation logic calculating detection accuracy, detection latency, and false-positive rates.
  • Developed FastAPI REST endpoints to expose simulation telemetry and metric summaries to the client dashboard.
# 6. Evaluation Metrics & Results

The simulator benchmarks emergency response effectiveness against simulated baselines using three key metrics:

  • Detection Accuracy: Ratio of correctly identified hazard incidents to total simulated events.
  • Detection Latency: Time elapsed (in simulation ticks) from incident trigger to agent notification.
  • False-Positive Rate: Frequency of spurious alerts triggered under noisy environmental inputs.

🩺 Skin Disease Detection — Deep Learning & Computer Vision
Deployed on Render Domain: Computer Vision (Educational Prototype)
Educational prototype only; not intended for medical diagnosis.
# 1. Project Overview

An applied AI/ML project demonstrating technical breadth in computer vision. Skin Disease Detection utilizes deep learning to classify common dermatological conditions from user-submitted images to assist exploratory educational screening.

# 2. Problem Addressed

Providing an accessible, rapid exploratory tool to demonstrate how lightweight convolutional architectures can identify visual characteristics of skin lesions on consumer-grade hardware without excessive computational latency.

# 3. Approach & ML Pipeline
  • Preprocessing Pipeline: Uploaded images are resized to the target input dimensions (224×224), normalized, and converted into tensors.
  • Model Architecture: Fine-tuned MobileNet architecture in TensorFlow using transfer learning for multi-class classification.
  • Web Deployment: Model inference served through a lightweight Python Flask web interface displaying predicted categories and confidence scores.
